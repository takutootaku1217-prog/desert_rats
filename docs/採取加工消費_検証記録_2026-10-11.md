# 採取→加工→消費：検証結果と取り出し待ちの切り分け

対象: `/workspace/desert_rats` のmain、製品修正コミット `d05b099743559350d5a77679ef871f6debe6c7c3`。
取得時の基準: `9f6be9a7f99b8d2f45f65119b7386463440e0e54`。
Linux / Godot `4.6.3.stable.official.7d41c59c4`。Windows / Godot 4.7.2は未検証。

結論: 共有重量の予約・解体予測の修正と基本循環は検証済み。60秒超の完成品待ち2件は自動で解消する有限待ちで、予約漏れ・再開漏れの証拠はない。ただし現在の60秒基準では不合格のまま。出来事ありの無操作放置は指定32分に届かず、無条件に「安定して生存」とは扱えない。今回の切り分けで製品の数値・優先度・休憩・襲撃の仕様は変更していない。

## 実行環境と正式な診断名

共通実行コマンド:

```sh
XDG_DATA_HOME=/tmp/desert-rats-checks/data \
XDG_CONFIG_HOME=/tmp/desert-rats-checks/config \
XDG_CACHE_HOME=/tmp/desert-rats-checks/cache \
godot --headless --path /workspace/desert_rats --fixed-fps 60 -s res://tools/<診断名>.gd
```

Godotは1プロセスずつ実行。XDGの指定は書き込み可能な診断用領域を使うため。乱数seed固定の通し試験は `_ready()` の `randomize()` の後にseedを適用する。固定fpsのヘッドレス実行は実時間より速く進められるため、ゲーム内時間を単純に12で割って実行所要時間とはしない。

消費診断では、診断専用に世界の時間と他の仲間を止め、在庫・初期加工品をゼロにする。木材と石は実際のポイント採取から収納、生肉は配置した獲物を回収・解体して取得する。`cook` / `firewood` / `repair_stone` の入力一度きり消費・指定数の出力・予約解除を確認。その製品を使い、食料1個消費で満腹度24→54、燃料1個消費で既定量補給、修理資材1個消費で既定量修理まで通した。燃料ゼロの速度上限15での走行も確認。製品の初期値は変更していない。

seedは基数+回番号。全試験fixed-fps60、time_scale12。

| 引数 | 初期条件 | 結果 |
|---|---|---|
| `32 2 12 500 0 vanilla` | 製品の初期設備・物資・仲間のまま、出来事だけ停止 | 32ゲーム内分×2回完走、exit 0 |
| `28 2 12 500 0 normal` | 診断専用に全設備あり、出来事停止 | 28ゲーム内分×2回完走、exit 0 |

食事は状態への遷移だけでなく、食料を持つ→消費・満腹度増加・累計増加で判定する。補給・修理も持ち物の消費と実回復を確認。25分以上の回で修理未達は失敗、ゲームオーバーで要求時間に届かなければ失敗。60秒の待ち基準は変更していない。

## 完成品取り出し待ちの切り分け

`trace` は `tools/loop_trace.gd` により、状態・予約・完成品・在庫・生活条件・敵・損傷をJSON行として記録する。乱数や判断には介入しない。

### manual seed701: 60.4ゲーム内秒の有限待ち

- 774.0秒: 油脂の加工で燃料2個が完成。
- 774.2秒: モモが1個を運び始め、残る1個に担当者がいない状態になる。加工担当予約は正常に解除され、`has_work_for_worker()` はtrue。
- 779.8秒: 最初の燃料を収納。疲労77.2で次の仕事より生活を優先。
- 785.4秒: モモがベッド休憩を開始。疲労78.5から回復する。チュー太も休憩し、830.6秒に復帰した後は加工より高い狩猟を選ぶ。ネズ吉も休憩中。
- 834.4秒: モモの疲労が19.7となり休憩終了。
- 834.6秒: モモが加工担当を再取得。担当不在は60.4秒で解消。
- 836.8秒: 残った燃料を取り出す。841.8秒に収納され、倉庫燃料12→13。

この間、モモのHP100、満腹度約48→44で、食事不足による停滞ではない。加工待ち注文はあるが、完成品は通常どおり先に取り出される。全28分中の担当不在待ち21件はすべて解消、最大60.4秒。修正前ソースでも同じ834秒の警告を再現した。

### 出来事ありvanilla seed501: 62.6ゲーム内秒の有限待ち

- 652.2秒: 燃料1個が出力に残り、担当不在となる。担当の取り残しはなく仕事は取得可能。
- モモは設備なしの簡易休憩中。チュー太は狩猟、補給、材料運搬を順に行う。ネズ吉は採取と運搬。
- 714.8秒: チュー太が材料運搬後、加工担当を取得。担当不在は62.6秒で解消。
- 715.2秒: 燃料を取り出し、720.4秒に収納、倉庫燃料6→7。続けて次の加工へ戻る。

712秒付近の満腹度は約51、食事は発生していない。担当再開の漏れはない。修正前ソースでも同じ712秒の警告を再現した。

判定: 両件は無期限デッドロックではなく、現在の生活優先・仕事優先順位と「担当不在60秒で失敗」という検査基準の不一致。60秒以内に必ず回収するという応答要件なら未達のまま。現状の意味を勝手に合格へ変えず、閾値引き上げもしていない。

## ゲームオーバーとの関係

- 1614.8ゲーム内秒: 既定方針「迎え撃つ」でサソリ5匹の襲撃開始。1616.2秒の車体耐久は約94.66。
- 一旦は迎撃し、1640秒頃に敵は残り1匹になる。
- チュー太とモモは疲労75超で生活行動へ。ネズ吉は疲労55.6でもストレス82.5による精神「限界」で休憩へ入る。
- 1640.4秒以降3匹とも簡易休憩。`_search()` は生活の必要を危険部位修理・迎撃より先に判定し、`REST_HERE` は回復完了・強い空腹・ベッドへの移動以外では中断しない。車体損傷域では休憩回復も半減する。近いモモは敵から疲労・HP被害を受け続ける。
- 1666.6秒（27分46.6秒）に車体耐久0。残敵はHP36、攻撃継続中。倉庫には食料10・燃料9・修理資材6、タンク燃料約77.79が残り、修理予約は空。加工出力は食料1個で、修理資材が出力に詰まっている状態ではない。

直接原因は、襲撃中に全員が生活回復を優先し迎撃・修理が止まる現行方針の組合せ。712秒の燃料取り出し待ちは720.4秒に解消済みで、死亡時も資材・燃料は十分ある。「昔から起きるから正常」とは結論せず、無操作でこの襲撃を生き残る保証が現行方針にないことを確認した。休憩中断・退避・自動逃走・敵の弱体化は仕様変更になるため実施していない。

トレース実行所要時間: manualは実時間14.18秒でゲーム内1680秒。出来事ありは実時間13.89秒、詳細項目追加後の再実行は17.52秒で、どちらもゲーム内1666.6秒に終了。出来事なしvanillaのトレースは実時間15.56秒でゲーム内1920秒完走。これらは実測値であり実際のプレイ時間や性能保証ではない。

## 次に判断する選択肢

1. **ゲーム方針を維持する場合**: 60秒超を遅延として記録し、担当が実際に取得可能か、生活状態が回復しているか、後で同じ出力が収納されたかを追う診断へ分ける案。無期限停止・予約不整合と区別する。現時点では検査基準の変更も未実施。
2. **取り出し応答を優先する場合**: 出力の回収を運搬仕事として誰が担当するか、狩猟・他の運搬より先に回収するかを決める必要がある。休憩を中断しないなら全員休憩時の60秒保証は別途検討が必要。既存の仕事割当仕様を変えるため未実施。
3. **襲撃中の生存を優先する場合**: 生活中の安全な退避、危険車体の修理・迎撃を優先する条件、自動的に既存の「振り切る」を選ぶか等の方針が必要。疲労・HPが危険な仲間へ作業を強制する影響も含めて決める。数値調整・敵弱体化で隠さない。

現時点で新たな製品コードの予約・再開不整合は確認できず、変更したのは任意トレースと記録のみ。開発ハーネスはこの判断結果を受けて整備する別工程。
