# ブーストコア比較試作（2026-10-19）

起点はリモート `gpt/rescue-return-loop` の `ea01cc2d7dc24759cb95f01eea549efb5b540397`。隔離ブランチ
`gpt/boost-core-prototype` で実装する。

## 範囲

- `V` キーまたは右上HUDの開始/解除で、プレイヤーが走行ブーストを操作する。
- 両コアとも速度は **1.5倍**。持続型は連続8秒・休止24秒、短時間型は連続2秒・休止6秒。
- 燃料とは別の **ブースト負荷**（0=休止直後、100=連続使用限界）を表示する。使用中は上がり、休止中は下がる。選択中コア、残り使用可能秒、休止で負荷が解消する残り秒をHUDに出す。
- 満杯でブーストを解除し、再開は次の `V` / HUD操作だけにする。過熱損傷・強制ロックは追加しない。
- コア交換は休止中だけにし、負荷率を引き継ぐ。交換だけで無料回復しない。
- コア選択・負荷・稼働状態を既存の手動保存に含める。旧セーブは持続型・負荷0・休止中に互換補完する。

## 既存制約との境界

倍率は目標速度に掛けるが、その後に既存の走行装置上限、天候、採掘地の停止、世界地図の到着距離上限を適用する。
燃料切れ、停車、帰還待ち、到着待ちでは開始できず、稼働中に該当した場合も解除する。燃料消費は既存どおり進行距離から計算するため、ブースト中は進む距離に応じて消費するが、新しい電力・加工・給電の仕組みはない。

初期値の速度60は既存の標準速度で、倍率1.5により通常時のブースト速度は90となる。両案の稼働率は 8/(8+24) = 2/(2+6) = 25% で等しい。差は一回の連続時間と回復の刻みだけで比較できるようにした。

## 検証

Godot `4.7.2.stable.official.ed1daf0bf`（指定の Windows console executable）で隔離 `APPDATA` を使用。

- `test_boost_core`: 持続・回復、同一速度、明示再起動、満杯解除、交換時の負荷維持、停車/燃料切れ/到着境界、保存復元。
- `test_boost_core_ui`: Viewport のスクリプト入力で V キー、開始/解除、両コア選択、HUD表記。
- Compatibility renderer（Intel Iris Xe）で HUD PNG を出力して目視確認。これは Viewport のスクリプト入力であり、OSレベル入力ではない。
- 既存 `test_world_flow`、`test_save_game`、`test_rescue_return`、`test_trouble_loop` を実行。すべて成功。

サンドボックスが返す仮想 `APPDATA` では `world_flow` の保存切替が権限エラーになった。実際の一時フォルダに同じ隔離設定で再実行すると成功したため、ゲーム実装の失敗としては扱わない。
