# 目的地型採取スポット：最小実装と検証

開始main: `f3f2e3999639378bd262d3a46780f2b16c2d2902`。既存の未push4コミットを保持。広域マップ・地域切替・永続保存・部屋拡張は追加しない。

## 遊び方と今回の範囲

右の「採取地点 (G)」→「この鉱床へ向かう」で街道脇の鉄鉱床を選ぶ。通常の速度・燃料・出来事で向かい、到着すると自動停車する。移動中の取消が可能。襲撃中/予報中なら入口で終了を待ち、敵を消して安全な地点に入った扱いにはしない。

地点には近場の小群と奥の密集群がある。初期は「近場のみ」、ボタンで全体に切替可能（着手済みの採取は通常の区切りまで続く）。既存の採取・運搬・加工・食事・休憩・修理を使う。残量は掘れる総量で、入手数は既存の道具と能力による。道中のランダム資源も従来どおり。

採取を切り上げると新規作業を止めて帰還待ちになる。掘りかけの袋、加工入力、補給/修理資材などは既存の届け先まで運ぶ。加工途中の注文・材料・進捗・完成品は拠点内に保持して担当を解放する。休憩・食事・気絶回復は既存の条件を使う。全員が拠点内に戻り、手持ちと搬入口残置がなくなったら「街道へ出発」が押せる。出発確定前は帰還を取り消せる。復帰の移動後、同じ地点へ再訪可能。

満載で収納できない物は、この地点では捨てず搬入口の残置台帳へ保持する。副産物や解体物も同じ窓口で保全。倉庫重量に無理に詰め込まず、空きができた分だけ回収する。残置があれば出発できず、画面に品名・数量・対処を表示する。帰還を取り消し、既存の制作や倉庫→作業場の運搬で空きを作ってから再度帰還する。無期限に黙って待つのではなく、解消条件と取消を表示する。

未採取の地点鉱床は出発時に残量を台帳へ移し、再訪時に同じ量を復元する。枯渇した鉱床も復活しない。画面外へのカメラ移動で削除しない。保持期間は現在のゲームだけで、ゲームのやり直し/アプリ終了後は保持しない。道中の通常の落とし物は従来どおり流れる。

## 調整用初期値

`data/quarry.gd` に集約。既存全体のバランス値を変えない。

| 項目 | 初期値 |
|---|---|
| 地点 | 街道脇の鉄鉱床1か所、既存IRON_OREを採取・精錬 |
| 片道 | 1200内部距離（HUD換算0.48km）。行き/街道復帰で各1回払う |
| 近場 | 1鉱床、残量12。停車した拠点の斜路に近い位置 |
| 奥 | 3鉱床、各24、合計72。斜路から徒歩距離が長い位置 |
| 収量/時間/袋 | 既存GatherDBの鉱床・道具・能力・袋3個をそのまま使用 |
| 倉庫 | 既存重量上限。重量による速度/燃費補正は追加しない |

現在は街道との往復を距離カウンタで表す1地点専用の状態機械。地理座標・道路網・広域地図ではない。往復距離は累積走行距離へ加算する。近場/奥は徒歩距離の違いで、目的地が2つあるわけではない。長居の利点と食料準備のバランスは今後の調整対象であり、今回の値で最適化済みとはしない。

## 安全と消耗

滞在/帰還待ち中は出来事の襲撃抽選・予報受付・発生処理を抑止し、旧周期出現も止める。到着前からいる敵や襲撃予報/発生中イベントは消さず、終わるまで街道側で待つ。街道移動/復帰中は元の出来事を維持する。

「襲撃なし」は無消耗の意味ではない。天候、故障、車体の時間摩耗、空腹、精錬の燃料消費、既存の狩猟事故は維持する。停車で移動燃料・走行装置の距離摩耗は止まるが、食材や木材は自動補充されない。既存の道中生物を狩る行動は残り、新しい生物戦闘は追加していない。部屋数4・寝室最大3ベッドは維持。

## 検証

Linux / Godot `4.6.3.stable.official.7d41c59c4`、fixed-fps60。既存ハーネスに `quarry` を登録し、coreへ追加。

```sh
python tools/run_checks.py --check quarry
python tools/run_checks.py --suite core
python tools/run_checks.py --suite extra
```

新診断 `tools/test_quarry.gd` は以下を確認する。

- 移動/取消/連打、到着停車、速度変更による誤出発防止。
- 近場のみ/全体、実AIの採取→倉庫→精錬、採取中の帰還と取消。
- 全員帰還・手持ち収納後だけ出発、街道復帰、枯渇/掘りかけ残量の再訪復元、ノード重複なし。
- 満載で袋/副産物を残置として保全、数量表示、出発阻止、取消、容量回復後に一度だけ回収。
- 予報/既存敵がいる間の入場待ち、滞在中の襲撃抑止、街道復帰後の襲撃経路復元。
- 停車で資源/生物が補充されず、移動燃料・走行装置摩耗が止まり、車体消耗が続く。
- 食料不足・疲労・負傷時の帰還と休憩回復、帰還待ちの食料実消費。
- 加工入力の運搬途中、加工途中の停止・取消後の再開、担当/予約の解放、材料の二重消費なし。
- 設備あり・初期備蓄・出来事なしの20ゲーム内分滞在。食事3回、修理2回、加工5回、全鉱床枯渇、残置なしで完走。完成品の担当不在待ち最長0秒、滞在後の全員帰還も成功。この条件は無期限自給や全天候での生存を保証しない。
