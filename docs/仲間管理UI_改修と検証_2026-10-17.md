# 仲間管理UIの改修と検証（2026-10-17）

## 採用範囲

- 上部の部署フィルターと、顔／短い名前のコンパクトな左一覧から個体を選び、右上の固定ヘッダーで顔・名前・現在行動・受け付けた個人指示・重要な不調を確認する。
- 個体情報を「概要」「装備・荷物」「仕事・能力」に分け、既存の「部署」タブは残す。閲覧・一括配属チェック・画面選択／追従は引き続き別の操作である。
- 概要は HP・満腹度・余力（`100 - fatigue`）・精神状態、使用中装備、運搬中の物資と届け先を一目で示す。装備4枠と運搬素材は実アイコンと短いラベルで別カードにし、余力アイコンの塗りと数字を同じ値にした。内部の疲労度計算は変更しない。
- 運搬中の見出しには通常運搬容量を併記し、現在の仕事はタブを切り替えても固定ヘッダーで常に確認できる。
- 装備・荷物は既存の武器、仕事補助、採取道具の全枠と、自動割り当て、個別変更、外す、変更不能理由を保持する。防具の存在しない枠は追加しない。
- `carrying` / `carry_n` は個人バッグとして扱わない。採取物・副産物・獲物の複数素材・加工材料・倉庫／作業場移送・燃料補給・修理資材を、実際の既存AIの状態と届け先から表示する。
- 個人の「帰還を指示」を追加した。受付時には荷物・予約・作業を直接変更せず、既存の帰還処理で安全な区切りと持ち物の通常配送を待つ。全員撤退の方針には触れない。休憩／食事の促しと収納操作は既存のまま残す。

- [非線形攻略・自動戦闘 統合設計 Ver.1](https://app.notion.com/p/3f3ec2f2a3c181828ae1c8bb8ab47d26): 日常の自動行動と、意味のある少数の個人指示を分ける方針を確認。

今回のユーザー採用UIを優先し、将来の装備枠・消耗品・戦闘機能は追加していない。

## 使い方

1. 通常HUDの仲間入口または `C` で管理画面を開き、左上の部署フィルターと顔／名前一覧から確認したい仲間を選ぶ。閲覧だけではゲーム内の選択やカメラ追従は変わらない。
2. **概要**で状態、使用中の装備4枠、運搬中の物資・数量・届け先を確認する。右上の「帰還を指示」「休憩を促す」は表示中の1人だけに作用し、理由や受付中は同じヘッダーに出る。「画面で選択・追従」だけが明示的に世界側の選択を変更する。
3. **装備・荷物**で全既存装備枠の自動割り当て・装備変更・外す・収納を行う。詳細な効果や採取効果は展開ボタンで表示する。**仕事・能力**で配属、チェック済み仲間への一括配属、効率、優先度、ランク、スキルを扱う。**部署**には既存の部署解放情報を残した。

## 証跡

`crew-ui-evidence-2026-10-17/` は実Godot描画のPNG。画面レイアウトと既存アセットを確認するため、撮影時だけ仲間1人の状態・装備・獲物素材・受付中の指示を注入して固定した。通常プレイの値を保存・変更する操作ではない。

- `crew-overview.png`: 固定ヘッダー、余力、装備4枠と獲物素材・数量・運搬先を分けた2枚の視覚カード。
- `crew-equipment-cargo.png`: 武器／仕事補助／採取道具を実アイコン付き分類カードで表示し、既存の装備変更・理由表示を保持した画面。
- `crew-work-ability.png`: 配属、複数選択対象、一括移動、効率、優先度を分離した画面。

## 検証

- Godot 4.6.3 stable / Linux、OpenGL Compatibility（llvmpipe）、Xorg dummy displayで実描画。
- `tools/test_crew_detail.gd` と `tools/test_crew_status.gd`: 3カテゴリ、固定ヘッダー、個人帰還指示、休憩／食事、余力の塗り・数字整合、全装備枠、獲物複数素材、加工材料の届け先、長名・スクロール、選択／一括／追従の分離を確認し、全件成功。
- `tools/test_production_ui.gd`、`tools/test_field_ui.gd`、`tools/test_haul_ui.gd`、`tools/test_weapon_ui.gd`: 運搬容量／現在の仕事、カテゴリを開いてからの手押し車・仕事補助・武器の実入力操作を確認し、全件成功。
- `python3 tools/run_checks.py --suite core`: 視覚カード仕上げ後に **62/62成功**（2026-10-17、`/tmp/desert-rats-core-visual-final/20261017T093606Z-68rxd8uk/results.json`）。検査中にゲーム／テストのソース変更はしていない。
- モック参照画像はChatGPT Libraryから解決できたが、この環境では取得済み一時URLのダウンロードに失敗した。採用方針の文章を根拠に実装し、モックの仮データは使用していない。
- 概要・装備・荷物・仕事・能力の3枚は実Godot画面だが、読みやすさと全ケース表示を確認するため撮影時だけ状態・装備・獲物素材・受付中指示を注入した。通常入力の動作は上記のUIテストで別途確認した。
- Windows実機同期・検証、Linux Godot 4.7.2、スマホ実機はこの作業では行っていない。
