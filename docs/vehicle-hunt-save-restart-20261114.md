## 試験の内容（2プロセス。既存の生存テストの共通部品 `survival_save_common.gd` を再利用）
- 保存側 `tools/test_vehicle_hunt_save_cycle.gd`（7チェック）: 通常の出発依頼と狩猟依頼（`world.request`、`request_hunt`）で走行し、車上狩猟が**自然に**1体を倒す。死骸がロープにあり、回収の進捗が途中（0.2秒／3.0秒）の時点で、通常のセーブを書く。倒した個体は、世界の生物台帳で独立に観測した死亡（1件）と、cargoの元の個体idが一致することを確認。
- 再開側 `tools/test_vehicle_hunt_save_restart.gd`（23チェック）: **別のGodotプロセス**で読み込み・適用。cargo・種・元の個体id・進捗・重量（cargoを一度だけ計上）・狩猟数・解体数が保存どおり、読み込みで何も収納されない、個体は同じ道路で `spent` のまま・生存していない、を確認。通常の刻みで回収が自然に完了し、**ちょうど1回**収納・解体される（倉庫の `item_added` シグナルの狩猟由来の追加で独立に観測。肉・皮・骨 各1）。肉は調理に回った分も含めてcargoの分だけ増え、総重量は変わらない（場所の移動で、新しい質量ではない）。
- その後、狩猟依頼なしで森へ進み、同じ道路を通って街へ戻る（元地点の再訪）。個体・死骸・cargoの不当な復活、依頼なしの新しい撃破、2回目の取得がないことを確認。
- **自然な再出現（regeneration）との区別:** 個体の再出現時刻（世界台帳の `respawn_at`、約114〜115秒）より前には生存個体として現れないこと、通常の移動を続けて再出現時刻を過ぎた後に初めて同じ個体が現れること、再出現した個体からは依頼なしに何も得られないこと（収納は1回のまま、狩猟数も同じ）を確認。
- **fixture/API/刻みの範囲:** seed・速度・食料の補充目標・仲間が採取しない設定は、既存の生存テストと同じ。入力は `world.request` と `request_hunt` のAPI。進行は通常の刻み（`main._process` と生物・敵・仲間の `_process`）。**注入していないもの:** 撃破、死骸、cargo、進捗の書き換え、時計の停止。保存の制限は解除していない（すべての保存テストと同じく、試験モードの旗を書き込みの瞬間だけ外す）。
